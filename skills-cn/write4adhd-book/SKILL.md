# write4adhd-book：祛魅体写作

用"祛魅体"写面向零基础读者的科普文章/文档。目标不是教会读者实操，而是**把门槛降到读者脚下**：读完他能用自己的话说出这东西大概是什么，并且不再觉得它高不可攀。"就这？"是读者心里自己冒出来的反应，**不是要写在纸上的台词**。

风格是手段不是目的：比喻、设问、收束句、俏皮话全部为"讲清"服务，读着像人在好好说话才算合格。反复宣布"其实很简单""祛魅一下"只会让文章显得刻意；让内容自己证明它不难。文风的全部规则和范文例句都在 `references/style-guide.md` 里。

## 工作流程

1. **明确三件事**（用户没说就先问或按默认推断）：
   - 写什么主题、面向谁（默认：零技术背景的普通爱好者）；
   - 体量与输出形式：短文（Markdown 或单页自包含 HTML，15 分钟能扫完）还是分章的"书"（多页 HTML 书站，每章一页）；选择标准见 `references/html-craft.md` 的"形态选择"；
   - 若是书且需要先探索一个技术项目/代码库再写作，先把探索做扎实，但**书里只写读者需要知道的那一层**，探索到的实现细节只用作直觉的底气，不搬进正文。
2. **动笔前必读** `references/style-guide.md`——文风是本 skill 的灵魂，逐条对照执行。
3. 若输出 HTML，**再读** `references/html-craft.md`，并复制对应模板作为起点（单页：`assets/skeleton.html`；书站：`assets/site/` 整目录），模板已内置全套样式、组件、Canvas 绘图辅助函数、主题切换和动画控制脚手架，不要从零手写页面。
4. 写作时先在大纲里定好：**一个贯穿全文的核心比喻**、每章的**收束句**、每张图的**人话图注**、**页首主副标题**（主标题说清本页讲什么、副标题引入核心比喻）。书形态还要先定**目录分页**：每页 1~3 节，目录页每章一句带钩子的简介。这几样是骨架，先想好再写正文。
5. 书形态不必一口气写完：按"目录页 → 逐章"的顺序分批产出，每写完一页都能独立打开验收；但核心比喻、术语译名、收束句的语气全书必须一致，写后续章前回顾已完成章节的导语和收束句。
6. 写完后按 `references/style-guide.md` 末尾的**自查清单**逐条检查（书形态逐页检查，再加一遍全书一致性检查）；HTML 产物建议用浏览器（或 playwright MCP 截图）检查亮/暗两种主题下的排版与图表渲染。

## 不可妥协的五条底线

1. **一个土味核心比喻贯穿全文**（如云存储 = "租在别人家的储物柜"），后文所有解释都回扣它。
2. **短**：章节短、段落短、句子短。连续纯文字不超过 4 行，超过就切小标题、列表或加粗关键词。
3. **每章结尾一句加粗的收束句**，把这一章压成读者带得走的一句话，给即时的"我懂了"奖励。句式跟着内容走，**不要每章套同一个模板**（连着三章"说白了：……"就是复读机）；压不成一句漂亮话时，朴素而准确的两句话更好。
4. **术语三步法**：先大白话描述现象 → 再引出学名（加粗 + 英文原文）→ 点到为止，不讲实现细节和边界条件。
5. **少讲公式多讲直觉**，宁可比喻"土"，不要抽象。对没定论的问题直接承认"不知道"，不装权威。
